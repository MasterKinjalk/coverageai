# Decision log

Decisions taken while freezing the v1.0 spec (2026-10-18). Defaults chosen by the orchestrator; team to confirm.

| ID | Issue | Decision |
|---|---|---|
| D1 | Wind direction: Draft spec says "toward", older Parameters PDF says "from" | Use **toward** (Draft is newer). `spec.yaml: wind_direction_convention` |
| D2 | "D" means drift risk in the proposal but deposition in the Draft spec | Four named outputs: `coverage_pct`, `deposition_ul_cm2`, `drift_frac`, `displacement_mm`. Selector minimizes `drift_frac`. |
| D3 | TP65 chart has no droplet class for 65 deg tips | Use the 80 deg column as proxy, flagged in catalog notes, unless the TeeJet catalog gives TP65 classes |
| D4 | DGX40 chart uses 10 in spacing, the rest 20 in | Use flow (gpm) only; recompute GPA at 20 in |
| D5 | Spray angle not on charts | TP65 65, XR 110, DGX40 40, ULD 120, 3D 100 (verify) |
| D6 | Speed and boom height controllable in Draft, treated as x in proposal | v1 selector picks (family, size, pressure); speed control is a stretch goal |
| D7 | Proposal M1/M2 dates passed without code | Compressed schedule in PLAN.md Section 5 |
| D8 | Windows Application Control blocks uv-managed Python 3.12 | Use system Python 3.14 via uv venv |
| D9 | WP-05: the annotated real WSP cards (2 manually annotated cards, 2,754 droplets, plus 127 pre-annotated real squares) are in Zenodo v2 (record 14010262) but its files are **restricted**; only v1 (13995950: 300 synthetic cards, CC BY 4.0, YOLOv8 polygons) downloads anonymously | Develop and test the loader and the B0/B1 vision stack on the 300 synthetic cards; `load_cards(root, "real")` returns [] until real files are placed under the data root. Request the real cards via the Zenodo access button and by email (draft in `reports/email_draft_simoes.md`, not sent). Until granted, the "real <= 5 pp" criterion is reported as untested (or evaluated on own phone photos of WSP). Synthetic px/mm is inferred (width/76 mm); no dpi is published. |
| D10 | With x = U*H/V_t and a 0.5 m threshold, a 2 m/s crosswind drifts ~87% of medium-droplet volume (unrealistic; the relation ignores nozzle exit velocity) | Keep threshold 0.5 m; add nozzle exit velocity v0 = 0.6*sqrt(2P/rho) with linear-drag relaxation (tau = V_t/g), so droplets cover part of H quickly before settling at V_t. Fine droplets still drift, medium/coarse mostly do not. |
| D11 | Proposal summary says sprayers commit to nozzle, pressure and speed; D6 left speed as an uncontrolled condition | Schema 1.1 adds optional `Setting.travel_speed_kmh` (None = use `Conditions.travel_speed_kmh`, identical to v1.0; hashing/equality of existing settings unchanged). When set it is the effective speed for `catalog.derive` (GPA = 5940*GPM/(MPH*W), so GPA ~ 1/speed), the predictor speed and GPA features (`features.featurize`) and the simulator (through derive). Selector speed control is opt-in: `selector.speed_options_kmh` (default empty = off) and `selector.speed_band_frac` (default 0.25). Candidate speeds are grid values inside the spec range `ranges.travel_speed_kmh` and within +-band of the segment current speed, because operators can adjust speed only within limits: slower gives more liquid per area and deposition, faster gives less. V stays volume per area (derive GPA at the effective speed). Evaluation: `experiments/eval_speed_control.py`, `results/speed_control_eval.{json,md}`. |

| D12 | D6/D11 left boom height as an uncontrolled condition, but release height sets fall time and hence drift | Schema 1.2 adds optional `Setting.boom_height_m` (None = `Conditions.boom_height_m`, identical to 1.0/1.1; equality/hash of existing settings unchanged) and `contracts.effective_boom_height_m(x, u)`. It is used by the simulator (`_inputs` and the batch path `_arrays_from_hidden`, RNG order untouched), `features.featurize` and the mock model; `catalog.derive` does not depend on height. Selector height control is opt-in and combinable with speed: `selector.boom_height_options_m` (default empty = off), `boom_height_band_frac` (0.25: automatic boom control moves height within seconds but only in a band around the canopy-following set point) and `boom_overlap_factor` (1.3). Minimum height per nozzle family from fan overlap, `catalog.min_boom_height_m`: H >= factor * S / (2 tan(theta/2)) with S = 20 in nozzle spacing and theta the fan angle (flat-fan boom-setup rule of thumb: pattern width = 1.3 x spacing, i.e. about 30% overlap; 100% overlap would be factor 2). Gives TP65 0.52 m, 3D 0.28, XR 0.23, ULD 0.19, DGX40 0.91 m (above the 0.75 m spec maximum, so never lowered/changed). Candidates also lie inside spec `ranges.boom_height_m` (0.30-0.75 m). Striping at low height is not modeled by the (uniform-field) simulator, hence the constraint. Evaluation: `experiments/eval_boom_control.py`, `results/boom_control_eval.{json,md}` (paired deterministic scoring). |
