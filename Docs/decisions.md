| D12 | D6/D11 left boom height as an uncontrolled condition, but release height sets fall time and hence drift | Schema 1.2 adds optional `Setting.boom_height_m` (None = `Conditions.boom_height_m`, identical to 1.0/1.1; equality/hash of existing settings unchanged) and `contracts.effective_boom_height_m(x, u)`. It is used by the simulator (`_inputs` and the batch path `_arrays_from_hidden`, RNG order untouched), `features.featurize` and the mock model; `catalog.derive` does not depend on height. Selector height control is opt-in and combinable with speed: `selector.boom_height_options_m` (default empty = off), `boom_height_band_frac` (0.25: automatic boom control moves height within seconds but only in a band around the canopy-following set point) and `boom_overlap_factor` (1.3). Minimum height per nozzle family from fan overlap, `catalog.min_boom_height_m`: H >= factor * S / (2 tan(theta/2)) with S = 20 in nozzle spacing and theta the fan angle (flat-fan boom-setup rule of thumb: pattern width = 1.3 x spacing, i.e. about 30% overlap; 100% overlap would be factor 2). Gives TP65 0.52 m, 3D 0.28, XR 0.23, ULD 0.19, DGX40 0.91 m (above the 0.75 m spec maximum, so never lowered/changed). Candidates also lie inside spec `ranges.boom_height_m` (0.30-0.75 m). Striping at low height is not modeled by the (uniform-field) simulator, hence the constraint. Evaluation: `experiments/eval_boom_control.py`, `results/boom_control_eval.{json,md}` (paired deterministic scoring). Evaluation verdict: default stays off. Open loop (no mismatch), height alone raises drift (nominal +0.0033 [+0.0010, +0.0057], learned +0.0027 [+0.0005, +0.0049]) with success unchanged; the nominal model is the simulator's expected physics here, so this is the selector's drift/volume trade-off choosing lower volume (24.83 to 21.42 GPA), not a misprediction. Open loop, speed+height lowers drift but success falls with the nominal model (-0.0200 [-0.0400, -0.0050]) and is unclear with the learned model (-0.0050 [-0.0250, +0.0150]). Closed loop, fast loop, speed+height lowers GPA (-2.5927 [-3.0943, -2.1093] med, -2.8117 [-3.3392, -2.3181] high) and drift at high (-0.0035 [-0.0066, -0.0005]; med -0.0021 [-0.0045, +0.0003], CI includes 0) but fraction met falls -0.0287 [-0.0362, -0.0206] and -0.0344 [-0.0444, -0.0244]; height alone also falls -0.0162 in both cells. With the fair oracle, height alone cuts drift (-0.0036 [-0.0052, -0.0019] med, -0.0060 [-0.0075, -0.0046] high) with no detectable loss in fraction met (-0.0050 [-0.0125, +0.0031], -0.0019 [-0.0087, +0.0050]). So the drift benefit appears only with the fair oracle under mismatch; with the nominal and learned models the selector spends the height freedom mainly on volume. The data do not isolate the cause beyond that. Speed+height still loses 2.1 to 2.7 pp under the oracle. Negative result for enabling by default (`results/boom_control_eval.md`). |
| D13 | The selector plans each segment with the wind x_k read at its start, but the plant applies a hidden AR(1) gust (phi 0.7, sd = mismatch `gust_sigma`), so a short-horizon wind forecast might help | Opt-in `forecaster=` of `loop.run_pass` / `run_passes_slow` (policies open, fast, fast_slow; `None` = default = off, bit-identical to before, tested in `tests/test_forecast.py`). Statistics only, no ML (`src/coverageai/forecast.py`, defaults in `config/spec.yaml: forecast`). Anemometer observes the realized segment-averaged wind of completed segments with noise sd 0.3 m/s (`obs_sd_ms`), never the upcoming one (`observe` is called after the plant call). Forecast target is the gust ratio r = observed / x.wind (skipped if x.wind < 0.5 m/s); direction is taken from x_k. Methods: `nominal` (r_hat = 1, logs only, equals off), `last`, `ewma` (beta 0.5), `ar1` (online shrunk least squares, 5 pseudo-observations toward mean 1 and 5 pseudo-pairs toward phi 0, phi clipped to +-0.95). Suffix `+gust`: selector plans with forecast + z sd (z = 1; sd from the last 10 residuals, sensor variance deducted), while the fast-loop bias and slow loop still learn from the point forecast. In the fast + slow loop one forecaster is carried over the 5 passes. `gust_oracle` (`GustOracleForecaster`) is a reference only: it reads the plant's gust for segment k, so it bounds any wind forecaster. Defaults were fixed on dev seeds 100-103, not tuned on seeds 0-19. Evaluation: `experiments/eval_forecast.py`, `results/forecast_eval.{json,md}` (320 cells: 4 mismatch x 4 presets x 20 seeds, arms off / last / ewma / ar1 / ar1+gust / nominal+gust / gust_oracle; pilot in `results/forecast_eval_pilot.*`). Verdict: negative result, default stays off. AR(1) cuts wind MAE by 0.059 m/s [-0.085, -0.033] (fast) and 0.099 [-0.130, -0.068] (fast + slow) against 0.558 for off, but segments meeting C_req change by -0.0 pp [-0.3, +0.3] and -0.2 pp [-0.4, +0.1]; the gust-aware arms add 0.4 to 0.6 % volume for no gain (same as `nominal+gust`); `gust_oracle` gives -0.5 pp [-0.9, -0.1] (fast) and -0.3 pp [-0.6, -0.0] (fast + slow), so the chosen settings are insensitive to wind (+30 % wind moves coverage by 0.07 to 0.18 pp) and no wind forecaster can help in this simulator. |
| D14 | Pure-ML `SprayModel` ignores the known droplet physics; a physics-first predictor is a candidate, but in this project the plant is the simulator, so physics accuracy against simulator data is circular | Opt-in `PhysicsResidualModel` (`src/coverageai/model/hybrid.py`; `integration` models `hybrid`, `hybrid_misspec`; default model stays `spray`, nothing changes with it off). Physics base = the simulator equations with no hidden mismatch and the mean WSP spread factor (equal to `oracle_nominal`; its interval is the coverage at the 10 % / 90 % spread-factor quantiles). Learned part = strongly regularized LightGBM residuals (300 trees, 15 leaves, min 200 rows per leaf, L2 = 10, lr 0.05) for coverage, retention, drift and displacement on the SprayModel features plus the physics outputs; coverage interval by conformalized quantile regression (q = 0.1 / 0.9, 15 % calibration split, one-sided offset per bound). Misspecified bases (`MISSPEC_PRESETS`: evaporation coefficient x1.30 / x0.75, drift threshold x0.75 / x1.25, spread factor x1.10 / x0.90, VMD x0.85 / x1.20, optimistic / pessimistic) are the honest test; the exact-base rows are an upper bound (circular). Results (`results/hybrid_eval.md`, `.json`; weights `models/hybrid_v1.joblib`, `models/hybrid_misspec_v1.joblib`; code `experiments/eval_hybrid.py`, `tests/test_hybrid.py`): offline the residual removes 94 to 99 % of the misspecification's excess error (coverage 97 to 99 %, drift 94 to 98 %, four splits x two presets); selector success on a wrong base 93.5 % vs 44.0 % for physics alone (SprayModel 92.5 %); closed loop, 20 seeds, med + high mismatch: hybrid on a wrong base recovers 98 % [88, 106] of the gap at +3.3 % [+2.1, +4.5] volume vs the fair oracle, 0.7 pp [0.3, 1.1] fewer sections on target than SprayModel with `fast_slow` (not better than pure ML), and far above physics alone in the open loop (0.822 vs 0.296 met); with the slow loop physics alone also reaches 0.978 met but at +9.7 % volume. Keep `spray` as the default. |
| D15 | The midterm oracle (`OracleModel`) also saw the per-card WSP spread factor, which is drawn when the card is sprayed and which no controller can know; it needed no safety margin, so the closed-loop volume criterion (<= +10 % vs the oracle) compared against an unreachable reference | New policy `oracle` = `loop.FairOracleModel`, the reference of the closed-loop criterion. For segment k it draws the hidden state exactly as the plant will (`simulator._draw_segment` on `default_rng([seed, k])`: AR(1) gust state, canopy interception, nozzle wear), discards the spread factor, predicts at the mean spread factor, and sets coverage_lo / coverage_hi at the `interval_q` / `1 - interval_q` quantiles of the spread factor's uniform range (`FAIR_ORACLE_INTERVAL_Q` = 0.1, the same one-sided level as SprayModel's 80 % CQR interval), so coverage_lo is the exact 10 % quantile of the true coverage given everything a controller could know. The selector's margin rule is unchanged. It thus measures perfect knowledge of the mismatch under the same risk policy. Falls back to the card-aware oracle (flag `fallback`) for plants without hidden state (mocks). The midterm oracle is kept as policy `oracle_card` and reported only as an unreachable bound. Definition and q fixed before the evaluation grid ran; q = 0.05 and 0.2 reported as sensitivity. Tests: `tests/test_fair_oracle.py`. Result (`results/closed_loop_summary.md`): the fair oracle itself uses +12.6 % [+11.2, +13.9] more volume than `oracle_card` (+9.8 % with no mismatch), the cost of irreducible card noise; against it, fast + slow recovers 96 % [80, 107] of the gap at +4.1 % [+2.8, +5.5] volume (criterion met). |
| D16 | The midterm slow loop (refit the 50,000-row LightGBM SprayModel on the measured cards with record weight 30) lowered reliability: the boosters fitted card noise and the CQR interval narrowed (dev-seed diagnostic: lower half-width 8.0-8.8 to 4.6-5.4 pp, true coverage below the lower bound in 19-26 % of segments, `results/closed_loop_notes.md`) | Slow loop redesigned as `feedback.ResidualCorrectedModel`, the default `slow_mode="residual"` of `loop.run_passes_slow` (this changes `fast_slow` results versus the midterm by design; the legacy refit is kept as `slow_mode="refit"` for the ablation). Point, lower and upper prediction are shifted by the offset; the interval width stays the base model's, so a refit cannot narrow the selector's margin. The fast-loop bias is reset at the start of each pass (`reset_bias_between_passes=True`) because it is measured against base + offset. | D20 | The proposal promises operator recommendations, but the app only showed what the controller chose. When a card reads below the target, the operator needs to know which control to change and by how much | New module `src/coverageai/recommend.py` (`recommend_for_logs`, `recommend`), shown in the app through `app_logic.recommendations` / `recommendation_frame`. For each section whose card reading is below C_req it searches the three in-cab controls with the fitted nozzle held: pressure in 5 psi steps inside the nozzle's catalog range and the spec family range, travel speed in 1 km/h steps inside `ranges.travel_speed_kmh`, boom height in 0.05 m steps inside `ranges.boom_height_m` and above `catalog.min_boom_height_m`. The model gives the effect of a change (predicted coverage at the new setting minus predicted coverage at the current one) and the card gives the level, so a model that is biased at that section still gives a usable step. Per control it reports the smallest move whose predicted gain closes the shortfall; controls are listed smallest move first (share of the control's legal range), then least added drift. If no single control is enough it searches joint moves (at most 6 values per control) and reports the smallest one that reaches the target (`combine`), or the best achievable setting (`unreachable`, with the advice to re-spray or fit a larger nozzle). A whole pass costs one batched model call, two if joint moves are needed. It works with any `contracts.Model` and never calls the simulator. Limits, stated plainly: the default target is C_req with no safety margin (`margin_pp = 0`), unlike the selector's interval margin; the LightGBM model is piecewise constant, so small steps can show zero or noisy gains (a 0.2 m boom move for +0.9 pp was seen); and no experiment has yet measured whether following the advice brings the section to target. |
