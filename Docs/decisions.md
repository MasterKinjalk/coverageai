# Decision log

Decisions taken while freezing the v1.0 spec (2026-10-18). Defaults chosen by the orchestrator; team to confirm.

| ID | Issue | Decision |
|---|---|---|
| D1 | Wind direction: Draft spec says "toward", older Parameters PDF says "from" | Use **toward** (Draft is newer). `spec.yaml: wind_direction_convention` |
| D2 | "D" means drift risk in the proposal but deposition in the Draft spec | Four named outputs: `coverage_pct`, `deposition_ul_cm2`, `drift_frac`, `displacement_mm`. Selector minimizes `drift_frac`. |
| D3 | TP65 chart has no droplet class for 65 deg tips | Use the 80 deg column as proxy, flagged in catalog notes, unless the TeeJet catalog gives TP65 classes |
| D4 | DGX40 chart uses 10 in spacing, the rest 20 in | Use flow (gpm) only; recompute GPA at 20 in |
| D5 | Spray angle not on charts | TP65 65, XR 110, DGX40 40, ULD 120, 3D 100 (verify) |
| D6 | Speed and boom height controllable in Draft, treated as x in proposal | v1 selector picks (family, size, pressure); speed control is a stretch goal |
| D7 | Proposal M1/M2 dates passed without code | Compressed schedule in PLAN.md Section 5 |
| D8 | Windows Application Control blocks uv-managed Python 3.12 | Use system Python 3.14 via uv venv |
| D9 | WP-05: the annotated real WSP cards (2 manually annotated cards, 2,754 droplets, plus 127 pre-annotated real squares) are in Zenodo v2 (record 14010262) but its files are **restricted**; only v1 (13995950: 300 synthetic cards, CC BY 4.0, YOLOv8 polygons) downloads anonymously | Develop and test the loader and the B0/B1 vision stack on the 300 synthetic cards; `load_cards(root, "real")` returns [] until real files are placed under the data root. Request the real cards via the Zenodo access button and by email (draft in `reports/email_draft_simoes.md`, not sent). Until granted, the "real <= 5 pp" criterion is reported as untested (or evaluated on own phone photos of WSP). Synthetic px/mm is inferred (width/76 mm); no dpi is published. |
| D10 | With x = U*H/V_t and a 0.5 m threshold, a 2 m/s crosswind drifts ~87% of medium-droplet volume (unrealistic; the relation ignores nozzle exit velocity) | Keep threshold 0.5 m; add nozzle exit velocity v0 = 0.6*sqrt(2P/rho) with linear-drag relaxation (tau = V_t/g), so droplets cover part of H quickly before settling at V_t. Fine droplets still drift, medium/coarse mostly do not. |
| D11 | Proposal summary says sprayers commit to nozzle, pressure and speed; D6 left speed as an uncontrolled condition | Schema 1.1 adds optional `Setting.travel_speed_kmh` (None = use `Conditions.travel_speed_kmh`, identical to v1.0; hashing/equality of existing settings unchanged). When set it is the effective speed for `catalog.derive` (GPA = 5940*GPM/(MPH*W), so GPA ~ 1/speed), the predictor speed and GPA features (`features.featurize`) and the simulator (through derive). Selector speed control is opt-in: `selector.speed_options_kmh` (default empty = off) and `selector.speed_band_frac` (default 0.25). Candidate speeds are grid values inside the spec range `ranges.travel_speed_kmh` and within +-band of the segment current speed, because operators can adjust speed only within limits: slower gives more liquid per area and deposition, faster gives less. V stays volume per area (derive GPA at the effective speed). Evaluation: `experiments/eval_speed_control.py`, `results/speed_control_eval.{json,md}`. |
| D12 | D6/D11 left boom height as an uncontrolled condition, but release height sets fall time and hence drift | Schema 1.2 adds optional `Setting.boom_height_m` (None = `Conditions.boom_height_m`, identical to 1.0/1.1; equality/hash of existing settings unchanged) and `contracts.effective_boom_height_m(x, u)`. It is used by the simulator (`_inputs` and the batch path `_arrays_from_hidden`, RNG order untouched), `features.featurize` and the mock model; `catalog.derive` does not depend on height. Selector height control is opt-in and combinable with speed: `selector.boom_height_options_m` (default empty = off), `boom_height_band_frac` (0.25: automatic boom control moves height within seconds but only in a band around the canopy-following set point) and `boom_overlap_factor` (1.3). Minimum height per nozzle family from fan overlap, `catalog.min_boom_height_m`: H >= factor * S / (2 tan(theta/2)) with S = 20 in nozzle spacing and theta the fan angle (flat-fan boom-setup rule of thumb: pattern width = 1.3 x spacing, i.e. about 30% overlap; 100% overlap would be factor 2). Gives TP65 0.52 m, 3D 0.28, XR 0.23, ULD 0.19, DGX40 0.91 m (above the 0.75 m spec maximum, so never lowered/changed). Candidates also lie inside spec `ranges.boom_height_m` (0.30-0.75 m). Striping at low height is not modeled by the (uniform-field) simulator, hence the constraint. Evaluation: `experiments/eval_boom_control.py`, `results/boom_control_eval.{json,md}` (paired deterministic scoring). Evaluation verdict: default stays off. Open loop (no mismatch), height alone raises drift (nominal +0.0033 [+0.0010, +0.0057], learned +0.0027 [+0.0005, +0.0049]) with success unchanged; the nominal model is the simulator's expected physics here, so this is the selector's drift/volume trade-off choosing lower volume (24.83 to 21.42 GPA), not a misprediction. Open loop, speed+height lowers drift but success falls with the nominal model (-0.0200 [-0.0400, -0.0050]) and is unclear with the learned model (-0.0050 [-0.0250, +0.0150]). Closed loop, fast loop, speed+height lowers GPA (-2.5927 [-3.0943, -2.1093] med, -2.8117 [-3.3392, -2.3181] high) and drift at high (-0.0035 [-0.0066, -0.0005]; med -0.0021 [-0.0045, +0.0003], CI includes 0) but fraction met falls -0.0287 [-0.0362, -0.0206] and -0.0344 [-0.0444, -0.0244]; height alone also falls -0.0162 in both cells. With the fair oracle, height alone cuts drift (-0.0036 [-0.0052, -0.0019] med, -0.0060 [-0.0075, -0.0046] high) with no detectable loss in fraction met (-0.0050 [-0.0125, +0.0031], -0.0019 [-0.0087, +0.0050]). So the drift benefit appears only with the fair oracle under mismatch; with the nominal and learned models the selector spends the height freedom mainly on volume. The data do not isolate the cause beyond that. Speed+height still loses 2.1 to 2.7 pp under the oracle. Negative result for enabling by default (`results/boom_control_eval.md`). |
| D13 | The selector plans each segment with the wind x_k read at its start, but the plant applies a hidden AR(1) gust (phi 0.7, sd = mismatch `gust_sigma`), so a short-horizon wind forecast might help | Opt-in `forecaster=` of `loop.run_pass` / `run_passes_slow` (policies open, fast, fast_slow; `None` = default = off, bit-identical to before, tested in `tests/test_forecast.py`). Statistics only, no ML (`src/coverageai/forecast.py`, defaults in `config/spec.yaml: forecast`). Anemometer observes the realized segment-averaged wind of completed segments with noise sd 0.3 m/s (`obs_sd_ms`), never the upcoming one (`observe` is called after the plant call). Forecast target is the gust ratio r = observed / x.wind (skipped if x.wind < 0.5 m/s); direction is taken from x_k. Methods: `nominal` (r_hat = 1, logs only, equals off), `last`, `ewma` (beta 0.5), `ar1` (online shrunk least squares, 5 pseudo-observations toward mean 1 and 5 pseudo-pairs toward phi 0, phi clipped to +-0.95). Suffix `+gust`: selector plans with forecast + z sd (z = 1; sd from the last 10 residuals, sensor variance deducted), while the fast-loop bias and slow loop still learn from the point forecast. In the fast + slow loop one forecaster is carried over the 5 passes. `gust_oracle` (`GustOracleForecaster`) is a reference only: it reads the plant's gust for segment k, so it bounds any wind forecaster. Defaults were fixed on dev seeds 100-103, not tuned on seeds 0-19. Evaluation: `experiments/eval_forecast.py`, `results/forecast_eval.{json,md}` (320 cells: 4 mismatch x 4 presets x 20 seeds, arms off / last / ewma / ar1 / ar1+gust / nominal+gust / gust_oracle; pilot in `results/forecast_eval_pilot.*`). Verdict: negative result, default stays off. AR(1) cuts wind MAE by 0.059 m/s [-0.085, -0.033] (fast) and 0.099 [-0.130, -0.068] (fast + slow) against 0.558 for off, but segments meeting C_req change by -0.0 pp [-0.3, +0.3] and -0.2 pp [-0.4, +0.1]; the gust-aware arms add 0.4 to 0.6 % volume for no gain (same as `nominal+gust`); `gust_oracle` gives -0.5 pp [-0.9, -0.1] (fast) and -0.3 pp [-0.6, -0.0] (fast + slow), so the chosen settings are insensitive to wind (+30 % wind moves coverage by 0.07 to 0.18 pp) and no wind forecaster can help in this simulator. |
| D14 | Pure-ML `SprayModel` ignores the known droplet physics; a physics-first predictor is a candidate, but in this project the plant is the simulator, so physics accuracy against simulator data is circular | Opt-in `PhysicsResidualModel` (`src/coverageai/model/hybrid.py`; `integration` models `hybrid`, `hybrid_misspec`; default model stays `spray`, nothing changes with it off). Physics base = the simulator equations with no hidden mismatch and the mean WSP spread factor (equal to `oracle_nominal`; its interval is the coverage at the 10 % / 90 % spread-factor quantiles). Learned part = strongly regularized LightGBM residuals (300 trees, 15 leaves, min 200 rows per leaf, L2 = 10, lr 0.05) for coverage, retention, drift and displacement on the SprayModel features plus the physics outputs; coverage interval by conformalized quantile regression (q = 0.1 / 0.9, 15 % calibration split, one-sided offset per bound). Misspecified bases (`MISSPEC_PRESETS`: evaporation coefficient x1.30 / x0.75, drift threshold x0.75 / x1.25, spread factor x1.10 / x0.90, VMD x0.85 / x1.20, optimistic / pessimistic) are the honest test; the exact-base rows are an upper bound (circular). Results (`results/hybrid_eval.md`, `.json`; weights `models/hybrid_v1.joblib`, `models/hybrid_misspec_v1.joblib`; code `experiments/eval_hybrid.py`, `tests/test_hybrid.py`): offline the residual removes 94 to 99 % of the misspecification's excess error (coverage 97 to 99 %, drift 94 to 98 %, four splits x two presets); selector success on a wrong base 93.5 % vs 44.0 % for physics alone (SprayModel 92.5 %); closed loop, 20 seeds, med + high mismatch: hybrid on a wrong base recovers 98 % [88, 106] of the gap at +3.3 % [+2.1, +4.5] volume vs the fair oracle, 0.7 pp [0.3, 1.1] fewer sections on target than SprayModel with `fast_slow` (not better than pure ML), and far above physics alone in the open loop (0.822 vs 0.296 met); with the slow loop physics alone also reaches 0.978 met but at +9.7 % volume. Keep `spray` as the default. |
| D15 | The midterm oracle (`OracleModel`) also saw the per-card WSP spread factor, which is drawn when the card is sprayed and which no controller can know; it needed no safety margin, so the closed-loop volume criterion (<= +10 % vs the oracle) compared against an unreachable reference | New policy `oracle` = `loop.FairOracleModel`, the reference of the closed-loop criterion. For segment k it draws the hidden state exactly as the plant will (`simulator._draw_segment` on `default_rng([seed, k])`: AR(1) gust state, canopy interception, nozzle wear), discards the spread factor, predicts at the mean spread factor, and sets coverage_lo / coverage_hi at the `interval_q` / `1 - interval_q` quantiles of the spread factor's uniform range (`FAIR_ORACLE_INTERVAL_Q` = 0.1, the same one-sided level as SprayModel's 80 % CQR interval), so coverage_lo is the exact 10 % quantile of the true coverage given everything a controller could know. The selector's margin rule is unchanged. It thus measures perfect knowledge of the mismatch under the same risk policy. Falls back to the card-aware oracle (flag `fallback`) for plants without hidden state (mocks). The midterm oracle is kept as policy `oracle_card` and reported only as an unreachable bound. Definition and q fixed before the evaluation grid ran; q = 0.05 and 0.2 reported as sensitivity. Tests: `tests/test_fair_oracle.py`. Result (`results/closed_loop_summary.md`): the fair oracle itself uses +12.6 % [+11.2, +13.9] more volume than `oracle_card` (+9.8 % with no mismatch), the cost of irreducible card noise; against it, fast + slow recovers 96 % [80, 107] of the gap at +4.1 % [+2.8, +5.5] volume (criterion met). |
| D16 | The midterm slow loop (refit the 50,000-row LightGBM SprayModel on the measured cards with record weight 30) lowered reliability: the boosters fitted card noise and the CQR interval narrowed (dev-seed diagnostic: lower half-width 8.0-8.8 to 4.6-5.4 pp, true coverage below the lower bound in 19-26 % of segments, `results/closed_loop_notes.md`) | Slow loop redesigned as `feedback.ResidualCorrectedModel`, the default `slow_mode="residual"` of `loop.run_passes_slow` (this changes `fast_slow` results versus the midterm by design; the legacy refit is kept as `slow_mode="refit"` for the ablation). The offline model is frozen; after every pass the correction is refit on ALL verified cards so far against the frozen base (r = C_meas - C_base, so refits never compound): a two-level normal model with a global offset (prior sd 5 pp, `SLOW_PRIOR_SD_PP`) and per-regime deviations on the fast loop's bins (|u_cross| x droplet group), tau^2 by method of moments, regime offsets shrunk toward the global one by empirical Bayes. Point, lower and upper prediction are shifted by the offset; the interval width stays the base model's, so a refit cannot narrow the selector's margin. The fast-loop bias is reset at the start of each pass (`reset_bias_between_passes=True`) because it is measured against base + offset. Variants were compared only on dev seeds 100-109 (`experiments/slow_loop_diagnostic.py`, `results/closed_loop_slow_diagnostic.md`), disjoint from the evaluation seeds 0-19. Known limitation: records of one pass share that pass's canopy/wear draw, so they are not independent. Tests: `tests/test_slow_loop.py`. Result (`results/closed_loop_summary.md`, ablation `gusty_afternoon`, med, 20 seeds): residual offset 0.966 met, 98 % [80, 125] recovery, vs legacy refit weight 30 0.832, -89 % [-308, -16] and weight 1 0.905, 12 % [-107, 53]; per-regime and global-only offsets are indistinguishable (98 % vs 95 %). The mean residual is removed after one pass but the within-pass residual variance stays at 27-32 pp^2 (negative result: card noise and gusts are irreducible). |
| D17 | The extensions D11-D13 (travel speed, boom height, wind forecaster) were reachable only through loop/selector arguments and experiment scripts, not in the demo app | Opt-in sidebar expander "Advanced controller options" in `app/main.py` (two checkboxes and a "Wind forecast" select), passed to `app_logic.run_pass_wrapper(speed_control=, boom_control=, forecaster=)`. Grids: `app_logic.SPEED_OPTIONS_KMH` = 8-30 km/h in 2 km/h steps (the grid of `experiments/eval_speed_control.py`; `eval_boom_control.py` uses a coarser 4 km/h speed grid) and `BOOM_HEIGHT_OPTIONS_M` = 0.30, 0.40, 0.50, 0.60, 0.75 m (the grid of `eval_boom_control.py`); the selector's own band and minimum-height rules (D11, D12) still restrict them. The options are set on the selector only for the duration of the call (like `lam`) and restored in a `finally` block; best_fixed keeps its single setting. Forecaster choices `app_logic.FORECAST_CHOICES` = off / last / ewma / ar1 / ar1+gust; it applies only to `loop.FORECAST_POLICIES` (open, fast, fast_slow; the oracles and best_fixed ignore it), and for fast_slow one forecaster object is shared by the learning passes and the displayed pass. URL parameters `?speed=1&boom=1&forecast=ar1` preset the controls (and open the expander). Default off; with all three off a run is bit-identical to before (`tests/test_app_logic.py::test_options_off_are_bit_identical_to_default`, plus tests for selector restore and forecaster policies). Same change: the noisy reader is reported with `used_vision=False` (shown as a simulated sensor, not image analysis), because the loop never reads its rendered card (`NoisyVerifier.measure_outcome`). |
| D18 | The v1 `SprayModel` (LightGBM, 100 trees, 50,000 rows) trains in 3 s on the CPU. The new machine has an RTX 5070 Ti; question: do more simulator data and a larger model trained on the GPU improve the predictor and the closed loop? The pip LightGBM wheel has no GPU learner, and LightGBM's CUDA learner is not supported on Windows | Opt-in XGBoost backend of `SprayModel` (`backend="xgboost"`, `device="cuda"` for training, single-thread CPU prediction like the LightGBM path; optional extra `gpu` = `xgboost>=3.0`). Same features, targets, q 0.1 / 0.9 quantile boosters and CQR offset; `n_estimators` and `max_depth` may be dicts per booster; `save(include_data=False)` drops the training rows (such a model cannot run the legacy refit slow loop, the default residual slow loop works). The LightGBM path is unchanged and bit-identical (prediction hashes of the shipped v1 file and of a refit are identical before and after). Depth-wise trees: on the GPU 3x faster than 32 CPU threads; leaf-wise trees are not faster on the GPU. Recipe `experiments/train_spray_v2.py`: v1 training rows plus 1,000,000 extra rows from the same generator (seed 20261019); depth in {6, 8, 10, 12}, learning rate 0.05, rounds by early stopping on a 10 % validation split (coverage scored against the noise-free expected coverage); per booster the cheapest point on the validation curves within 2 % of the best; scored on the v1 random-split test rows. Results (`results/model_v2.md`, `results/model_v2_fast.md`): coverage MAE 2.844 -> 2.785 pp (noise floor 2.773; paired difference -0.060 [-0.078, -0.042]), error against the noise-free coverage 0.643 -> 0.243 pp, drift MAE 0.0030 -> 0.00056, displacement 3.41 -> 0.76 mm. More data alone (LightGBM, v1 config, 1.04M rows) reaches 0.401 pp, tuning alone (XGBoost, v1 rows) 0.513 pp. Negative result: on the held-out 3D nozzle family drift MAE gets worse (0.0072 -> 0.0130); the deeper trees extrapolate worse to an unseen family. The uncapped v2 (146 MB) needs 135 ms per `predict_batch` over 547 candidates (target 20 ms; v1 5.8 ms; idle CPU, `results/predictor_timing.json`). `v2_fast` caps rounds x depth at 1800 per booster: same coverage error, drift 0.00068, displacement 1.08 mm, 15.9 ms median (p95 23.6 ms), 29.5 MB. Closed loop (`results/model_v2_closed_loop/`, 20 seeds, noisy verifier, paired; the v1 rerun reproduces `results/closed_loop_spray.json` exactly): v2_fast minus v1, share of segments meeting C_req, open +0.42 pp [+0.09, +0.74], fast +0.73 [+0.42, +1.03], fast + slow +0.41 [+0.12, +0.68]; volume within +-0.5 %; drift +2 to +3 % relative (+0.0003 to +0.0005); fair-oracle gap recovery 99 % [83, 111] at +4.3 % volume vs 96 % [80, 107] at +4.1 % for v1. Uncapped v2: +0.02 / +0.46 [+0.16, +0.77] / +0.23 [-0.07, +0.51] pp. Part of the v2_fast gain may come from its slightly wider 80 % interval (9.18 pp vs 8.94 for v2 and 9.03 for v1), which makes the selector margin more conservative. Default stays v1 (team to confirm): the gain is under 1 pp, the final report and scorecard are built on v1, and the 3D-family extrapolation is worse. Use v2 with `--model-path models/spray_model_v2_fast.joblib` or `COVERAGEAI_MODEL`. The v2 files are gitignored; regenerate with `uv run --no-sync python experiments/train_spray_v2.py --cost-cap 1800 --tag fast --skip-small` (16 min on the GPU, with evaluation). Also fixed: since schema 1.1 `experiments/make_dataset.py` wrote Setting's optional `travel_speed_kmh` / `boom_height_m` (None) over the Conditions columns, so a regenerated `v1.parquet` had all-NaN speed and height and retraining failed. The shipped v1 model predates this and is unaffected; the fixed dataset reproduces its stored training features exactly. |
