# CoverageVision AI: notes for Claude Code

Closed-loop precision spraying, in simulation (ABE 598, Fall 2026). A physics simulator sprays a
field section, a model predicts coverage and drift, a selector picks the nozzle setting, a card
reader measures coverage on a water-sensitive paper card, and feedback corrects the next
prediction. The product is the Streamlit app; the experiments and reports are the evidence.
Everything is simulation-based. Do not write anything that reads as field validation.

## Where to start

- Open work and current status: `Docs/NEXT_STEPS.md`. Read it first.
- Design decisions: `Docs/decisions.md` (D1 to D22). Add a row for every new design choice, in
  the same style: the issue, the decision, the evidence, and what was not tested.
- Setup and commands: `README.md`. Scope and success criteria: Table 1 of
  `Docs/CoverageVisionAI_Project_Proposal (1).pdf`. `PLAN.md` is the original plan, kept for history.
- Results: `results/scorecard.md` is generated by `reports/final/build.py`. Edit the builder, not
  the file. `reports/midterm/` is frozen as its committed HTML and PDF; do not rebuild it.

## Commands

```bash
uv run --no-sync pytest -o addopts="" -q         # full suite, about 6 minutes, with the summary line
uv run --no-sync pytest tests/test_nozzle_lock.py -k best_nozzle
uv run --no-sync streamlit run app/main.py       # the app
uv run --no-sync python reports/final/build.py --no-pdf
uvx ruff check --select F src app                # unused names; run after every edit
```

Always pass `--no-sync` (or set `UV_NO_SYNC=1`). A plain `uv run` restores the CPU torch from the
lock file over the CUDA build. The repo path has a space: quote it. `pyproject.toml` already adds
`-q` to pytest, so a second `-q` hides the pass/fail summary; use `-o addopts=""` when you need it.

## How the code fits together

- `contracts.py`: the records (`Conditions` x, `Setting` u, `Outcome`, `Prediction`, `SegmentLog`)
  and the module protocols. `config/spec.yaml` holds every physical and tuning number.
- `simulator.py` + `physics/`: the plant. `catalog.py`: nozzle charts and the 547-setting
  candidate grid (43 nozzles x 5 psi steps). `scenarios.py`: weather presets.
- `model/predictor.py`: `SprayModel` (LightGBM v1 is the default; XGBoost v2 is opt-in, D18).
  `model/hybrid.py`: physics + residual model (opt-in, D14).
- `selector.py`: `ConstrainedSelector` (eq. 2), opt-in speed, boom-height and nozzle-lock options.
- `loop.py`: `run_pass` (one pass, six policies), `run_passes_slow`, the two oracles.
  `feedback.py`: fast bias loop and slow residual correction. `forecast.py`: opt-in wind forecast.
- `vision/`: `render.py` (card renderer), `classical.py` (reader B0), `unet.py` (reader B1).
- `integration.py`: `build_modules(model, verifier)` assembles the stack.
- `recommend.py`: operator advice (which of pressure, speed, boom height to change, D20).
- App: `app_logic.py` is all non-UI logic and returns one `PassResult` per run.
  `field_anim.py` turns it into the replay payload; `app/field_run_view.py` is the canvas
  (plain JS in a Python string); `app/main.py` is widgets and layout only; `app/labels.py`
  holds every display name; `spray_lab.py` + `app/spray_lab_view.py` are the simulator tab.

## Rules that are easy to break

1. **New controller features are opt-in and default off.** With them off, results must not
   change. `tests/test_defaults_golden.py` pins 11 default runs by digest; if it fails you
   changed default behaviour. Regenerate the digests only after a deliberate, logged decision.
   The app is the one place where a default may differ (it holds one nozzle per field, D19).
2. **Random streams are a contract** (see the docstrings of `simulator.py` and `loop.py`).
   Section k draws from `default_rng([seed, k])`; the renderer, noisy reader and anemometer use
   `[seed, k, 1]`, `[seed, k, 2]`, `[seed, k, 3]`. The hidden draws come first and do not depend
   on the setting. Do not add a draw in front of them.
3. **The plant has state inside a pass** (AR(1) gust, canopy, wear). Never call
   `modules.simulator` for a what-if. Use the model, or a `copy.deepcopy` of the simulator as
   `app_logic.replay_card` and `render_cards` do.
4. **The module stack is shared and cached** (`st.cache_resource`). Anything set on the selector
   for one run (`lam`, speed and boom grids, `nozzle_lock`) must be restored in a `finally`
   block, as `run_pass_wrapper` does. `RecordingSelector` forwards reads only: set attributes on
   its `.inner`.
5. **Saved models are rebuilt with `cls(**params)`.** Renaming or removing a constructor argument
   of `SprayModel` or the hybrid model breaks `models/*.joblib`. Reordering
   `spec.nozzle_families` fails on load; reordering `droplets.class_order` changes a feature
   silently and gives wrong predictions with no error.
6. Compare nozzles by `(family, size)`, not by `Setting` equality: a `Setting` also carries the
   optional speed and boom height.
7. In the fast loops the selector runs twice per section. The logged `bias` is the final
   regime's; the one used to select is `extra["selection_bias"]`.
8. In the app, the replay and the charts below it must read the same numbers: both go through
   `app_logic.loop_numbers`. Card pictures in the replay come from recording proxies around the
   renderer and verifier, so a run renders and reads each card once.

## Evaluations

Paired comparisons on the same seeds, paired-bootstrap 95 % CIs, the fair oracle (`oracle`) as
the reference, `oracle_card` only as an unreachable bound. Development seeds stay separate from
evaluation seeds 0 to 19. Report negative results as negative. A single app run is an anecdote.
State what was not tested (for example, D19 and D20 have no multi-seed evaluation yet).

## Working habits for this repo

- Other Claude sessions may edit this checkout. Check `git status`, stage explicit paths, never
  `git add -A`, never stash. To compare against HEAD use a `git worktree` in a temp folder and
  run the main `.venv` python with `PYTHONPATH=<worktree>/src`.
- App tests (`streamlit.testing`) are slow. Use `?verifier=perfect&cards=0` unless the test is
  about cards. To look at the page, drive headless Chrome with the `Browser` class in
  `experiments/readme_media.py`; the replay canvas can be rendered standalone from
  `field_run_view._HTML`.
- For large multi-line edits write a small patch script to a temp file and run it; long shell
  heredocs with quotes have failed here.
- Docs and UI text: plain English, short sentences, no hype. UI text shows display names from
  `app/labels.py`, never internal identifiers (a test checks this).
- Append one line per session to `Docs/ai_usage_log.md` (date, task, model, what it produced).
